=============================
Changelog for Thunderbird 102
=============================

The following WebExtension API changes were introduced in Thunderbird 102.


compose
-------

.. raw:: html

   <div class="changelog-api-header">
     <span class="changelog-api-label">api</span>
     <a href="../compose.html">compose</a>
   </div>

- :small:`function` :ref:`getActiveDictionaries <compose.get^active^dictionaries>` — Returns a :ref:`compose.ComposeDictionaries <compose.^compose^dictionaries>` object, listing all installed dictionaries, including the information whether they are currently enabled or not.
- :small:`function` :ref:`saveMessage <compose.save^message>` — Saves the message currently being composed as a draft or as a template. If the save mode is not specified, the message will be saved as a draft. The returned Promise fulfills once the message has been successfully saved.
- :small:`function` :ref:`setActiveDictionaries <compose.set^active^dictionaries>` — Updates the active dictionaries. Throws if the :value:`activeDictionaries` array contains unknown or invalid language identifiers.
- :small:`event` :ref:`onActiveDictionariesChanged <compose.on^active^dictionaries^changed>` — Fired when one or more dictionaries have been activated or deactivated.
- :small:`type` :ref:`ComposeDetails.additionalFccFolder <compose.^compose^details.additional^fcc^folder>` — An additional fcc folder which can be selected while composing the message, an empty string if not used. Has no effect when the message is saved as a draft or template; the additional copy is only created when the message is actually sent or queued for sending. The permission :permission:`accountsRead` is required to use this property.
- :small:`type` :ref:`ComposeDetails.attachVCard <compose.^compose^details.attach^v^card>` — Whether or not the vCard of the used identity will be attached to the message during send.
- :small:`type` :ref:`ComposeDetails.deliveryFormat <compose.^compose^details.delivery^format>` — Defines the MIME format of the sent message (ignored on plain text messages). Defaults to :value:`auto`, which will send html messages as plain text, if they do not include any formatting, and as :value:`both` otherwise (a multipart/mixed message).
- :small:`type` :ref:`ComposeDetails.deliveryStatusNotification <compose.^compose^details.delivery^status^notification>` — Let the sender know when the recipient's server received the message. Not supported by all servers.
- :small:`type` :ref:`ComposeDetails.overrideDefaultFcc <compose.^compose^details.override^default^fcc>` — Indicates whether the default fcc setting (defined by the used identity) is being overridden for this message. Setting :value:`false` will clear the override. Setting :value:`true` will throw an *ExtensionError*, if :value:`overrideDefaultFccFolder` is not set as well. The permission :permission:`accountsRead` is required to use this property.
- :small:`type` :ref:`ComposeDetails.overrideDefaultFccFolder <compose.^compose^details.override^default^fcc^folder>` — This value overrides the default fcc setting (defined by the used identity) for this message only. Either a :ref:`folders.MailFolder <folders.^mail^folder>` specifying the folder for the copy of the sent message, or an empty string to not save a copy at all. The permission :permission:`accountsRead` is required to use this property.
- :small:`type` :ref:`ComposeDetails.priority <compose.^compose^details.priority>` — The priority of the message.
- :small:`type` :ref:`ComposeDetails.returnReceipt <compose.^compose^details.return^receipt>` — Add the *Disposition-Notification-To* header to the message to requests the recipients email client to send a reply once the message has been received. Recipient server may strip the header and the recipient might ignore the request.
- :small:`type` :ref:`ComposeDictionaries <compose.^compose^dictionaries>` — A *dictionary object* with entries for all installed dictionaries, having a language identifier as *key* (for example :value:`en-US`) and a boolean expression as *value*, indicating whether that dictionary is enabled for spellchecking or not.

messages
--------

.. raw:: html

   <div class="changelog-api-header">
     <span class="changelog-api-label">api</span>
     <a href="../messages.html">messages</a>
   </div>

- :small:`function` :ref:`createTag <messages.create^tag>` — Creates a new message tag. Tagging a message will store the tag's key in the user's message. Throws if the specified tag key is used already.
- :small:`function` :ref:`deleteTag <messages.delete^tag>` — Deletes a message tag, removing it from the list of known tags. Its key will not be removed from tagged messages, but they will appear untagged. Recreating a deleted tag, will make all former tagged messages appear tagged again.
- :small:`function` :ref:`updateTag <messages.update^tag>` — Updates a message tag. Throws if the specified tag key does not exist.
- :small:`type` :ref:`MessageHeader.headersOnly <messages.^message^header.headers^only>` — Some account types (for example :value:`pop3`) allow to download only the headers of the message, but not its body. The body of such messages will not be available.
